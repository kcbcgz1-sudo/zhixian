## 1. 核心用户流程（User Flows）

MVP 只保证 4 条主流程闭环，其余全部后置。

### 1.1 新用户上手流程（激活）
```
下载/打开 → 引导页(3屏讲清"同龄人实测·无套路·广州户外")
→ 微信/手机号一键注册 → 选择兴趣(钓鱼/登山, 可多选) → 城市默认"广州"
→ 直接进入"广州钓鱼/登山"干货信息流(已有种子内容)
→ 首次浏览干货帖 → 引导收藏第一条(激活消费侧)
```
关键：**注册后立刻看到真实干货**，不给空页面。城市在 MVP 写死广州，不让用户选空城市。

### 1.2 干货消费流程（主路径 · 决定留存）
```
信息流(按可信度排序) → 点开帖子详情 → 看结构化信息+实拍图
→ 收藏 / 有效评论(问路况、问收费) → (可选)关注作者
→ 回到信息流继续刷
```

### 1.3 干货发布流程（供给侧 · 决定内容壁垒）
```
点"发布" → 选垂类(钓鱼/登山) → 进入"结构化发帖模板"(非自由文本框!)
→ 逐项填写(钓点/线路名、定位、参数、避坑) → 上传实拍图(≥3 张提示)
→ AI 实时规整(排版、补参数提示、去水词) → 预览"干货度评分"(满足几项)
→ 提交 → 进入审核队列 → 审核通过后发布 + 结算积分
```
关键：**发帖入口就是结构化表单**，从源头逼出"干货"，这是与小红书自由发帖的根本区别。

### 1.4 互动与举报流程（社区纯净）
```
帖子/评论 → 点赞(同城同好+1分) / 收藏 / 评论
举报入口 → 选原因(虚假/广告/搬运/无效) → 提交 → 进审核 → 属实则对方扣分下架
```

## 3. 关键页面明细（核心 3 页）

### P4 · 情报信息流（首页）
- 顶部：垂类切换 `钓鱼 | 登山`（默认上次选择）；右上角搜索。
- 卡片内容（信息密度适中、大字）：封面实拍图、标题、**核心结构化标签**（如钓鱼：`免费·水库·鲮鱼·有停车`；登山：`适中·8km·爬升400m·有补给`）、作者名+称号、收藏数。
- 排序：默认按**可信度分**（见第 6 节），非按点赞。顶部可切"最新"。
- 空态：MVP 靠种子内容避免空态；仍需设计"暂无内容，去发布第一条"兜底。

### P6 · 结构化发帖（最重要）
- **不是**一个大文本框。是**分区表单**：
  - 区块 A：基本（垂类已选、标题、正文简述）
  - 区块 B：**结构化字段**（按垂类不同，见第 4 节；必填项标红）
  - 区块 C：实拍图上传（提示"≥3 张真实照片可评为干货，网图/盗图会被下架"）
  - 区块 D：避坑提醒（选填但加分）
- 实时"干货度进度条"：满足几项结构化标准 / 是否达到干货门槛（≥3 项）。
- AI 辅助按钮："帮我规整"——AI 把口水话整理成标准攻略、提示缺失参数（AI 只做整理与提示，**不编造事实**）。

### P5 · 帖子详情
- 顶部实拍图轮播 → 结构化信息卡（表格化呈现，一眼看全参数）→ 正文 → 避坑提醒(高亮) → 地图/定位 → 作者卡 → 评论区(鼓励"实测评论")。
- 互动条：收藏 / 点赞 / 评论 / 举报。
- 可信度徽标：显示该帖"干货认证"标识与作者称号，强化信任。

## 5. 数据模型（MVP 建库蓝本）

> 关系型为主；垂类专属字段用 `attributes` JSON 存，兼顾灵活与简单。

### 5.1 实体关系（概览）
```
users 1─* posts *─1 categories
posts 1─* post_images
posts 1─* interactions(点赞/收藏/评论) *─1 users
posts 1─* reports *─1 users(举报人)
users 1─* points_ledger
users 1─* user_titles      (后置，先留表)
cities 1─* posts
groups *─1 cities          (同城群组, 简化)
```

|---|---|---|

| user_id | FK | |
| category | 枚举 | fishing/hiking |
| city, district | | |

## 6. 积分与可信度算法（精确定义）

### 6.1 积分规则（MVP 简化版，AI/规则结算，全部写入 points_ledger）
| 行为 | 积分 | 限制 |
|---|---|---|
| 发布干货帖（≥3 结构化项 + 审核通过） | +30 | 按帖 |
| 稀缺避坑实测帖（含 warn_tips + 实拍 + 审核加标） | +40 | 运营/AI 标记 |
| 被同城同好点赞 | +1 | 单人单帖 1 次，单日上限 +50 |
| 帖子被收藏 / 收到有效实测评论 | +2 | 每帖每人 1 次计分 |
| 灌水评论/跨城批量点赞/刷量 | 0 | 规则拦截，不计分 |

**扣分/风控**
| 情形 | 处理 |
|---|---|
| 虚假情报、举报属实 | −50，帖子下架 |
| 广告/灌水/引流 | 清空当日积分，限制发帖 1 天 |
| 多次违规 | 冻结积分权益（达人/段位后置） |

> MVP 阶段"一机多号、夜间刷分"等复杂反作弊**先用简单规则**（同人同帖去重、单日上限、同城判定），完整 AI 反作弊放第二阶段。

### 6.2 可信度分 trust_score（信息流排序用）
可解释、可调参，MVP 不上黑盒模型：

```
trust_score =
    W1 * 结构化完整度分(quality_score)     # 每满足 1 个结构化字段 +10；达干货门槛额外 +20
  + W2 * 有效互动分                          # 收藏×2 + 同城点赞×1 + 有效评论×2，单帖设上限防刷
  - W3 * 风险分                              # 被有效举报×N、无图、疑似广告/搬运
  + 新帖曝光加权(发布 48h 内 +B，随时间衰减)
  + 作者可信度权重(段位/达人, 后置, MVP 记 0)

MVP 建议初值：W1=1.0, W2=0.6, W3=1.5, B=30(线性衰减到0)
```
设计意图：**结构化质量 > 互动热度**，且风险惩罚权重最高，从排序层面压制水帖/广告，保证"真实靠谱"的第一体验。参数上线后按数据调。

## 7. 埋点事件清单（对齐第一阶段 KPI）

| 事件 | 触发 | 关联 KPI |
|---|---|---|
| app_open | 打开 App | DAU/WAU |
